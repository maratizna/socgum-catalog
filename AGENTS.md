# AGENTS.md — Каталог номеров СоцГума

Контекст для AI-агентов, работающих с этим репозиторием. Читатель файла не знает проекта — рассказывай по фактам из кода, не додумывай.

## Что это

Статический сайт-каталог номеров концертов студенческого творческого объединения «СоцГум» (Самарский университет). Живёт на GitHub Pages: https://maratizna.github.io/socgum-catalog

Цепочка данных: **Google Таблица → build.py → site/ → GitHub Pages**. Данные в коде не хранятся — только в таблице.

## Команды

- **Сборка:** `python build.py` (нужен Python 3.12+, `pip install -r requirements.txt` — openpyxl, Pillow, Jinja2).
- Источник данных — переменные окружения: `SHEET_ID` (боевой), `SHEET_FILE=<путь.xlsx>` (локальная проверка), `SHEET_XLSX_URL`. Без них собирается `data/demo.xlsx` с пометкой «демо».
- **Важно:** если в таблице ошибка, сборка завершается НЕУСПЕШНО намеренно — на сайте остаётся прошлая версия, а в отчёте указаны лист и строка. Не «чините» это поведение.
- **Деплой:** push в `main` → GitHub Actions (.github/workflows/build.yml) собирает и публикует. Вручную ничего заливать не нужно.

## Структура

- `build.py` — сборщик (~данные, проверки, обложки, генерация). Единственный скрипт сборки.
- `templates/` — шаблоны Jinja2. `number.html` — страница номера (плеер, кнопки действий, комментарии), `index.html` — главная, `person.html` — страница человека, `base.html` — обвязка. Файлы с `_` — частички (include).
- `assets/` — статика: `social.js` (вся Firebase-логика: комментарии, оценки, плейлисты, пагинация по 5 через startAfter), `style.css`.
- `covers/` — исходные обложки номеров (`<ID>.jpg/.png/.webp`).
- `data/` — `demo.xlsx` (демо-данные) и `template.xlsx` (пустой шаблон таблицы).
- `tools/` — `make_workbook.py` и Apps Script для таблицы.
- `firebase/` — `firestore.rules` (источник истины для правил; публикуются в консоль вручную).

## Соглашения

- Язык интерфейса — русский; комментарии в коде — тоже русские, как в существующем коде.
- Сайт тёмный (`--night`-палитра в style.css), оранжевый акцент; заголовок «Номера СоцГума» — фирменный шрифт.
- Firebase-проект: `socgum-catalog-sandbox` (конфиг в `config.json`). Админ определяется коллекцией `admins` (документ с ID = uid пользователя), НЕ по e-mail.
- Комментарии: пагинация по 5 через `startAfter` (соц. JS), «популярные» грузятся целиком; у номеров старше 7 дней кэш час вместо 10 минут.
- Не ломай PWA: `sw.js.tpl` — service worker, офлайн-режим обязан продолжать работать.

## Словарь интерфейса

Пишем одинаково во всех шаблонах и JS:

- **номер** — единица каталога и выступления; не «видео» и не «работа», кроме специального случая направления вне сцены.
- **концерт** — событие, внутри которого стоит номер.
- **постановщик** и **участник** — роли человека в номере.
- **момент** — метка времени в записи концерта.
- Действия: **«Слушать трек»**, **«В плейлист»**, **«Смотреть с …»**, **«Показать ещё»**.
- «Показать ещё» везде выглядит одинаково. Размер шага разный осознанно: главная показывает по 16 карточек, потому что они уже есть в HTML и не тратят чтения; комментарии и вкладки профиля — по 5, потому что каждая страница читается из Firestore и подтягивает связанные данные.

## Кэш чтений Firebase

Сроки заданы один раз в `assets/social.js` в `TTL`; новые ключи добавлять туда же и сразу писать, что их сбрасывает:

- `me` — 3 дня: вход/выход, подтверждение и отзыв страниц.
- `pub` — 10 минут: сохранение профиля, заявки, свои комментарии и оценки.
- `comments` — 10 минут: отправка, правка, удаление, скрытие и лайк комментария; смена фото/ника.
- `commentsOld` — 1 час: то же для комментариев к номерам старше 7 дней.
- `note` — 2 минуты: сохранение слова постановщика.
- `avatar` — 14 дней: смена фото, ника, соцсетей, вход/выход.
- `likers` — 30 секунд: постановка или снятие лайка у этого комментария.

## Что трогать осторожно

- `templates/number.html` — блок `.num-actions` объединяет кнопки «Слушать трек»/«Поделиться»/«В плейлист» в одну flex-строку; не возвращай их колонкой.
- `firebase/firestore.rules` меняется синхронно с `social.js` (новые коллекции/поля → новые правила).
- Не коммитьте сессии агентов, бэкапы и временные файлы (`_out/`, `*.tmp`, `таблица-копия*`).

## Проверка изменений

Локально: `python build.py` должен отработать без ошибок и собрать `site/`. Глобально: после push проверять https://maratizna.github.io/socgum-catalog/ (публикация ~5 минут).
