# Каталог номеров СоцГума

Статический сайт-каталог. Данные ведутся в Google Таблице, сайт собирает робот (GitHub Actions) и публикует на GitHub Pages.

## Как это работает

Google Таблица → `build.py` (проверка данных, оптимизация обложек, генерация страниц) → GitHub Pages.

Если в таблице ошибка, сайт не обновляется, а в отчёте сборки (вкладка Actions → последняя сборка → Summary) написано, на каком листе и в какой строке.

## Что где лежит

- `data/template.xlsx` — пустой шаблон таблицы, `data/demo.xlsx` — демо-данные (выдуманные)
- `covers/` — обложки номеров: файл `<ID номера>.jpg` (или .png/.webp) либо имя файла в столбце «Обложка»
- `templates/`, `assets/` — внешний вид сайта
- `config.json` — название сайта, адрес, ссылка на сайт СоцГума
- `build.py` — сборщик

## Подключить свою таблицу

1. В Google Таблице: Настройки доступа → «Все, у кого есть ссылка» → «Читатель». Редакторов добавляйте по почте отдельно.
2. Скопируйте ID таблицы из адреса: `docs.google.com/spreadsheets/d/<ID>/edit`.
3. В репозитории: Settings → Secrets and variables → Actions → вкладка Variables → New repository variable: имя `SHEET_ID`, значение — ID.
4. Actions → «Собрать и опубликовать каталог» → Run workflow.

Без переменной `SHEET_ID` собираются демо-данные с пометкой «Демонстрационные данные».

## Меню «Каталог» в Google Таблице

Файл `tools/apps-script/Code.gs`. Установка: в таблице Расширения → Apps Script → вставить код вместо имеющегося → Сохранить → обновить страницу.

- Создать структуру (пустую или с демо-данными): листы, заголовки, выпадающие списки, текстовые форматы времени.
- Проверить таблицу: те же проверки, что у робота, ошибки красятся красным.
- Собрать список людей: добавляет на лист «Люди» всех, кто упомянут в номерах.
- Обновить сайт сейчас: запускает сборку на GitHub. Нужен токен: GitHub → Settings → Developer settings → Fine-grained tokens, репозиторий только `socgum-catalog`, право Actions: Read and write. Вводится один раз через Каталог → Ввести GitHub-токен.

## Локальная сборка

    pip install -r requirements.txt
    python build.py                 # демо
    SHEET_ID=... python build.py    # из Google Таблицы
    SHEET_FILE=путь.xlsx python build.py

Результат — папка `site/`.

## Постоянные ссылки

Каждая страница и фильтр имеют адрес, который не меняется при переименовании:

| Что | Адрес | Из чего берётся |
|---|---|---|
| Номер | `/n/<ID>/` | столбец «ID» листа «Номера» |
| Человек | `/p/<ID>/` | столбец «ID» листа «Люди» |
| Концерт | `/?c=<ID>` | столбец «ID» листа «Концерты» |
| Направление | `/?d=<ID>` | столбец «ID» листа «Направления» |
| Момент записи | `/n/<ID>/?t=2:15` | время по записи концерта целиком: `135`, `2:15`, `1:02:03`, `1h2m3s` |

ID проставляет меню «Каталог → Проставить ID» (и сам, когда вписано название). Заполненные ID скрипт никогда не меняет.
Переименовывать концерт, направление или человека нужно через «Каталог → Переименовать выделенное»: меню поправит все упоминания в «Номерах», а ID и ссылка останутся прежними.
Если ID не заполнен, сборка берёт адрес из названия и предупреждает, что он сменится при переименовании.

## Важно знать

- Расписание (раз в сутки) GitHub отключает, если в репозитории 60 дней нет активности. Тогда сборку можно запустить кнопкой Run workflow, и расписание снова включится.
- Шрифты Unbounded и Golos Text лежат в `assets/fonts/` вместе с лицензиями (OFL).


## Комментарии, вход и страницы постановщиков (Firebase)

Включается блоком `"firebase"` в `config.json`. Пустой блок: сайт остаётся полностью статическим.

- Вход: Google или e-mail с паролем (регистрация с именем). Окно «Войти» в шапке.
- Комментарии на странице номера; время вида `1:23:45` в тексте становится кнопкой, которая перематывает запись концерта. Все такие метки собираются в блок «Моменты».
- Постановщик может: заявить свою страницу кнопкой «Это моя страница» (имя в аккаунте совпало с таблицей — подтверждается сразу, иначе подтверждает администратор), править «О себе», ссылку и фото, писать «слово постановщика» на своих номерах, отвечать в комментариях со значком «Постановщик».
- Администратор: скрывает и удаляет комментарии, подтверждает заявки, отзывает доступ, кнопкой «Обновить список» передаёт базе список людей из таблицы (кабинет: `/account/`).
- Правила базы: `firebase/firestore.rules`. Переезд на другой аккаунт: `docs/PEREEZD.md`.
- Ссылки на комментарии: `/n/<ID>/#c-<id комментария>`.
