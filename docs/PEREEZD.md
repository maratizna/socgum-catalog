# Переезд на корпоративные аккаунты

Всё, что привязано к личным аккаунтам, перечислено ниже. Порядок важен.

## 1. Таблица и скрипт (Google)
1. С корпоративного аккаунта: загрузить `data/template.xlsx` (пустая) или `data/demo.xlsx` в Google Диск → открыть как Google Таблицу.
2. Расширения → Apps Script → вставить `tools/apps-script/Code.gs`. Сверху поменять `SITE_URL`, `REPO` (новый репозиторий).
3. Доступ к таблице: «Все, у кого есть ссылка» → читатель (сборщик читает её без входа).
4. Каталог → Создать структуру (если таблица пустая), затем «Проставить ID».
5. Каталог → Ввести GitHub-токен (см. п. 2.4), если нужна кнопка «Обновить сайт сейчас».
6. Формы для заполнения: Каталог → Формы для заполнения → Создать формы. Скрипт попросит разрешения (Формы, Диск, триггеры): нужно подтвердить под корпоративным аккаунтом. Ссылки появятся на листе «Формы».
7. Обложки: в формах «Номера списком» и «Дополнить номер» вопрос «Загрузка файлов» скрипт создать не умеет. Откройте каждую форму для редактирования (ссылки в столбце D листа «Формы»), добавьте вопрос типа «Загрузка файлов» с названием точно как в `docs/FORMY.md` (в обеих формах «Обложка номера (до 1,5 МБ)»). Включите «только изображения», 1 файл, не обязательный. Затем Каталог → Формы для заполнения → Создать формы ещё раз: вопрос переедет в конец формы.
8. Если администратор Google Workspace запретил открывать файлы Диска по ссылке для всех, обложки из форм сайт не скачает. Тогда разрешите внешний доступ для этого аккаунта или кладите обложки в папку `covers` репозитория.

## 2. GitHub
1. Новый репозиторий в организации: залить содержимое этой папки.
2. Settings → Pages → Source: GitHub Actions.
3. Settings → Secrets and variables → Actions → Variables → `SHEET_ID` = id новой таблицы (из её адреса).
4. Токен для кнопки «Обновить сайт сейчас»: fine-grained token только на этот репозиторий, право Actions: Read and write.
5. `config.json`: `site_url` (новый адрес сайта), `home_url`. Запустить workflow вручную.

## 3. Firebase (комментарии, вход, страницы постановщиков)
1. console.firebase.google.com → создать проект под корпоративным аккаунтом (план Spark, Analytics не нужен).
2. Firestore Database → Create database (режим production, регион поближе, например eur3).
3. Authentication → Sign-in method: включить Google (имя для пользователей, почта поддержки) и Email/Password.
4. Authentication → Settings → Authorized domains → добавить адрес сайта (например `компания.github.io`).
5. Project settings → Your apps → Web (`</>`) → скопировать публичный конфиг в `config.json`, блок `"firebase"` (`apiKey`, `authDomain`, `projectId`, `appId`).
6. Firestore → Rules → вставить `firebase/firestore.rules` → Publish.
7. Войти на сайте один раз (любым способом). В Authentication → Users скопировать свой UID.
8. Firestore → Data → Start collection `admins`, Document ID = UID, поле `role` = `admin`. Так назначается администратор. Других администраторов добавлять так же.
9. Открыть страницу «Кабинет» на сайте под администратором: список людей и номеров передастся в базу сам (или кнопка «Обновить список»).
10. (Рекомендуется) Google Cloud → APIs & Services → Credentials → API key проекта → ограничить HTTP referrers адресом сайта.

## 4. Что не переносится
- Старые комментарии из прежней базы `fir-7eb86` (если нужны: их ключ — адрес старой страницы Tilda; соответствие задаётся столбцом «Старый адрес» в листе «Номера»; импорт делается отдельно).
- Аккаунты и комментарии пробного проекта `socgum-catalog-sandbox`: после переезда проект можно удалить (Project settings → Delete project).

## 5. После переезда
- Удалить пробный проект Firebase, старый репозиторий и токены.
- Спросить согласие людей на публикацию имён и фото. Определить второго администратора.
- Раз в два месяца проверять, что ночной запуск (cron) не отключён GitHub из-за неактивности репозитория.

## 6. Что ещё нужно помнить
- Правила базы публикуются вручную (шаг 6 выше) и каждый раз, когда файл `firebase/firestore.rules` меняется: без этого не работают новые функции (оценки, лайки). Файл всегда актуальный, его целиком вставляют вместо старого.
- Ссылки на формы внизу сайта берутся с листа «Формы» вашей таблицы (столбец «Ссылка для сотрудников»). Нет листа или ссылок — блок не показывается. Лист создаёт меню «Каталог → Формы для заполнения → Создать формы».
- Оценки (1–5 по четырём критериям и общему впечатлению) лежат в коллекции `ratings`, один документ на человека и номер. Список оценок номера читается целиком (до 500), при очень большом числе оценок понадобится счётчик.
- Фильтр мата работает в браузере (список корней в `assets/social.js`, блок «фильтр мата»). Обойти его можно через консоль браузера, поэтому остаются кнопка «Скрыть» у администратора и удаление комментариев.
