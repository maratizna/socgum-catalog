# Развитие сайта без нагрузки на базу

Глубокий разбор: какие функции можно добавить, почти не тратя обращения к Firestore.
Документ дополняет `ОПТИМИЗАЦИЯ-ЗАПРОСОВ.md` (как экономить на существующем) и
`_out/ИДЕИ-функциональности.md` (общий банк идей).

---

## 0. Главный принцип: три бесплатных слоя

Архитектура сайта уже устроена так, что база нужна только для социального слоя
(комментарии, оценки, плейлисты, профили). Всё остальное можно строить на трёх
бесплатных слоях:

| Слой | Что это | Стоимость | Уже используется |
|---|---|---|---|
| **Сборка** (build.py) | Данные таблицы запекаются в HTML и `catalog.json` при каждой сборке | 0 чтений навсегда | весь каталог, `hot.json`-мета, `rate.json` |
| **Браузер** (localStorage) | Персональные данные посетителя живут у него на устройстве | 0 чтений, 0 записей | настройки, кэш, сортировка комментариев |
| **Агрегатный документ** | Один документ вместо многих, обновляется редко и пакетно | 1 чтение на просмотр | `rateAgg/{номер}`, `buzz/{номер}` |

Ниже все идеи разложены по этим слоям. Для каждой указана цена в чтениях/записях
Firestore — если там нули, функция бесплатна при любом трафике.

Текущий масштаб для оценки: 26 номеров, 197 человек, `catalog.json` ≈ весь каталог
одним файлом, который браузер и так грузит для поиска.

## 1. Слой сборки: функции, запечённые в статику (0 чтений)

### 1.1 «Номер дня» на главной
Детерминированный выбор номера по дате: `numbers[день_года % N]`. Одинаков для всех
посетителей без единого запроса, меняется каждый день, зазывает вглубь каталога.
Реализация: 5 строк в app.js, данные уже на странице.
**Цена: 0. Эффект: ежедневный повод вернуться.**

### 1.2 Страница «Каталог в цифрах»
При сборке известно всё: номеров, участников, постановщиков, концертов, часов
записей (по `start`/`end`), распределение по направлениям и годам, рекорды
(самый длинный номер, самый большой состав, самый активный постановщик по
количеству номеров). Рендерится как красивая инфографика-страница при сборке.
**Цена: 0. Эффект: «живость» и повод делиться (красивые цифры репостят).**

### 1.3 Хронология / календарь концертов
Страница `/timeline/`: концерты по датам, внутри — номера. Все даты есть в таблице
(поле `Дата`, `Учебный год`). Сборка просто раскладывает по временной оси.
Прямо отвечает миссии «проследить преемственность и развитие».
**Цена: 0. Эффект: навигация по истории объединения.**

### 1.4 «Этот день в истории СоцГума»
Из дат концертов: «7 ноября 2024 года прошёл Гала-концерт». Блок на главной,
вычисляется на клиенте из `catalog.json` (даты концертов там есть).
**Цена: 0. Эффект: ностальгия и вовлечение ветеранов.**

### 1.5 Метки «Новинка» и «Недавно добавлено»
У сборки есть дата генерации и даты концертов; номера последнего концерта или
добавленные за последние N дней получают плашку. Уже частично есть сортировка
«Недавно добавленные» — осталось визуально выделить.
**Цена: 0.**

### 1.6 RSS/Atom-лента новых номеров
Сборка пишет `feed.xml` (10–20 последних номеров с обложками). Подписчики читают
в любом RSS-клиенте, Telegram-боты могут репостить автоматически.
**Цена: 0. Эффект: канал распространения без соцсетей.**

### 1.7 Программка концерта для печати
Страница концерта с `print`-стилями: красивая программка (название, дата,
номера по порядку с участниками) одной кнопкой «Распечатать / сохранить PDF».
Всё уже на странице, нужны только `@media print` стили.
**Цена: 0. Эффект: офлайн-атрибутика, полезно самому коллективу.**

### 1.8 Экспорт плейлиста/списка номеров
Кнопка «Скопировать список» на странице концерта и в плейлисте: текст вида
«1. Rhythm 0 — коллектив Luna (3:42)». Для афиш, постов, рассылок.
**Цена: 0.**

## 2. Слой браузера: персональное без регистрации (0 чтений, 0 записей)

localStorage уже используется для настроек и кэша. Его лимит (~5 МБ) позволяет
хранить тысячи записей о поведении посетителя.

### 2.1 «Смотреть позже» (закладки без входа)
Кнопка-закладка на номере, список на главной («Ваша полка»). Хранится локально,
работает гостям — а гостей большинство. При входе можно (опционально, 1 раз в сутки)
сливать в аккаунт по схеме из `ИДЕЯ-история-просмотров.md`.
**Цена: 0 (базово). Эффект: заменяет регистрацию для главного сценария «сохранить».**

### 2.2 Черновики комментариев
Автосохранение набранного текста в localStorage каждые пару секунд с привязкой
к номеру. Ушёл со страницы — вернулся, текст на месте. Сейчас случайный уход
со страницы теряет рецензию, написанную полчаса.
**Цена: 0. Эффект: больше длинных осмысленных рецензий (концепция платформы!).**

### 2.3 Прогресс «Сколько каталога вы смотрели»
Из истории просмотров (когда появится) или просто из открытых страниц:
«Вы смотрели 14 из 26 номеров», полоса прогресса на главной + «осталось 3 номера
хореографии». Чистая геймификация без сервера.
**Цена: 0.**

### 2.4 Локальные достижения
Те же бейджи из банка идей (C1), но считаемые на клиенте из истории и поведения:
«5 номеров подряд», «вся хореография», «ночной зритель» (смотрел после полуночи).
Показываются тостом и на полке. Для студенческой аудитории — работает.
**Цена: 0. Позже можно синхронизировать с аккаунтом (1 документ, как история).**

### 2.5 «Вы уже смотрели» на карточках
Приглушённая плашка «смотрено» на карточках номеров из каталога — по локальной
истории. Решает главную боль при росте каталога: «я это видел или нет».
**Цена: 0.**

### 2.6 Запоминание позиции просмотра
`resume`-элемент на странице номера уже заложен в разметке. Дописать: каждые
10 секунд воспроизведения — позиция в localStorage; при возврате —
«Продолжить с 2:15». Особенно ценно для длинных концертов.
**Цена: 0. Эффект: досмотры длинных записей.**

### 2.7 Персональные рекомендации
Из локальной истории: чаще смотрит хореографию → «Ещё хореография»; смотрел
номера Саблиной → «Другие номера Светланы». Простой подсчёт по полям
`catalog.json`, без ML.
**Цена: 0. Эффект: персонализация без сервера и без учёта личности.**

## 3. Слой агрегатов: социальное за 1 чтение (почти 0)

Паттерн уже доказан `rateAgg` и `buzz`: вместо «читать много» — «читать один
документ, который кто-то один посчитал». Пересчёт у нас уже есть (кнопка админа,
читает всё, пишет сводки). Его можно расширить — пересчёт и так читает все
комментарии и оценки, добавочная запись пары документов бесплатна.

### 3.1 `meta/top.json` — топы за одно чтение
При пересчёте админ пишет один документ: топ-10 номеров по оценке, топ-10
постановщиков (среднее по их номерам), топ-10 рецензентов по лайкам, «номер
недели». Любая страница читает **1 документ** и строит рейтинги.
**Цена: 1 чтение на просмотр страницы рейтингов (кэш 10 мин).**
Закрывает сразу: B3 (топ постановщиков), C2 (зрительские симпатии),
«лучшие номера» на главной.

### 3.2 Выделенные рецензии (A1 из банка идей)
Админ ставит флаг `featured` на 1–2 комментария. На странице номера выделенные
идут первыми (0 лишних чтений — они уже в загруженной странице). На главной —
лента «Рецензии недели»: запрос `comments where featured == true limit 10`,
один на посетителя, кэш час.
**Цена: ≤10 чтений на просмотр главной с кэшем. Эффект: стандарт качества рецензий.**

### 3.3 «Сейчас смотрят» (пульс сайта)
Осторожно: настоящий presence — дорого (запись на каждого зрителя). Дешёвая
имитация: `meta/pulse` — документ со счётчиками «за сегодня: N комментариев,
M оценок», обновляется тем же пересчётом или при действиях (1 инкремент
в существующий батч записи — бесплатно, batch и так пишется).
**Цена: 1 чтение + 0 добавочных записей. Эффект: ощущение живого места.**

## 4. Улучшения UX без новых данных вообще

### 4.1 Клавиатурная навигация
`/` — фокус в поиск, `←`/`→` — листать номера концерта (порядок есть в `position`),
`Esc` — закрыть попапы. Для «каталожного» сценария перебора номеров — большое
удобство. **Цена: 0.**

### 4.2 Быстрый просмотр обложек
На главной по наведению/удержанию — увеличенная обложка и факты (без перехода).
Данные уже на странице. **Цена: 0.**

### 4.3 Пустая правая колонка страницы номера
Найдено при обзоре: на широком экране справа пусто. Перенести туда «Похожие
номера» или «Ещё этот коллектив» (данные есть на странице). **Цена: 0.**

### 4.4 Кнопка «Смотреть» поверх обложки
Сейчас перекрывает лица при некоторых соотношениях сторон — привязать к нижней
кромке постера. **Цена: 0.**

### 4.5 Онбординг первого визита
Три строки-точки на главной при первом заходе (localStorage-флаг): «ищите по
участнику», «комментируйте без регистрации → с Google», «собирайте плейлисты».
Скрывается навсегда после закрытия. **Цена: 0.**

## 5. Игровые/виральные механики (0 чтений)

### 5.1 «Угадай номер по кадру»
Мини-игра из обложек: показывается обложка/кадр, 4 варианта названия. Все данные
локальны. Раз в день новый раунд (детерминированно по дате, как «номер дня»).
**Цена: 0. Эффект: виральность, глубокое знание каталога аудиторией.**

### 5.2 Сравнение двух номеров
«Этот или этот?» — выбор из двух карточек; итог — просто забава, ничего не пишется.
Вариант с подсчётом голосов — только через агрегат (1 документ на пару) — дороже,
отложить. **Цена: 0 (без подсчёта).**

### 5.3 Карточка «Поделиться мнением»
Уже есть генерация карточки в «Поделиться». Добавить вариант карточки с оценкой
человека (звёзды/числа на красивой обложке) — для сторис. **Цена: 0.**

## 6. Что НЕ делать (ловушки по нагрузке)

| Идея | Почему дорого | Альтернатива |
|---|---|---|
| Счётчик просмотров на каждый номер | запись на каждый визит = самая дорогая функция сайта | история просмотров (localStorage) |
| Настоящий «онлайн» / presence | heartbeat-записи от каждого | `meta/pulse` агрегат (п.3.3) |
| Полноценные уведомления о новых номерах | нужен сервер и подписки | RSS (п.1.6) + «номер дня» |
| Поиск по тексту комментариев | индексация, чтение всех комментариев | поиск по каталогу уже есть и бесплатен |
| Голосование «номер vs номер» с подсчётом | записи на каждый клик | без подсчёта (п.5.2) или агрегат раз в день |

## 7. Дорожная карта (влияние ÷ цена)

**Этап 1 — чистый клиент, неделя вечеров:**
Номер дня (1.1), черновики комментариев (2.2), запоминание позиции (2.6),
метки «Новинка» (1.5), клавиатура (4.1), «смотрено» на карточках (2.5 — после истории).

**Этап 2 — сборка:**
«Каталог в цифрах» (1.2), RSS (1.6), timeline (1.3), программка для печати (1.7).

**Этап 3 — агрегаты (после первого пересчёта с расширенным кодом):**
`meta/top.json` + страница рейтингов (3.1), выделенные рецензии (3.2).

**Этап 4 — игры:**
«Угадай по кадру» (5.1), локальные достижения (2.4), прогресс каталога (2.3).

История просмотров (уже расписана в `ИДЕЯ-история-просмотров.md`) — ключевой
зависимый кусок для этапов 1 и 4: на ней стоят «смотрено», прогресс,
рекомендации и достижения. Её стоит сделать первой из крупных.
